# Hydarium Launcher : fiche de reprise

Version 0.10.12 (journal des versions plus bas, jusqu’à 0.10.52) · Windows en priorité, structure prête pour macOS et Linux · Électron (interface web + processus principal Node).

## 1. Où on en est
**Fait** : connexion Microsoft réelle, instances Vanilla / Fabric / Quilt, mods Modrinth (dépendances, intégrité, statuts, incompatibilités bloquantes), serveurs avec « rejoindre », code de partage, import depuis Prism / MultiMC / Minecraft officiel, assistant de bienvenue, notifications système, journaux, installeur Windows avec Java embarqué.
**Volontairement pas fait** : quêtes, cosmétiques, points et paiement (décision du porteur du projet, à ajouter plus tard).
**Pas encore fait (cahier des charges v1.9)** : Forge / NeoForge, amis, chat, vocal, galerie de captures (seule la liste des fichiers existe), catalogue de mods hors instance, thèmes personnalisés, activité Discord, réglages experts (dossier des instances, téléchargements simultanés), « Mon serveur », mod client en jeu, code de modpack court (demande un serveur), import CurseForge / ATLauncher / Modrinth App, langues (interface en français seulement), mise à jour automatique, icône `.ico`, signature de l’exe.
**Jamais exécuté** : tout a été écrit sans pouvoir lancer l’application (pas de Windows ni de réseau à ce moment). Seule la syntaxe a été vérifiée. Premier réflexe : `npm start`, regarder les journaux (section 5).

## 2. Lancer et fabriquer
- Développement : Node.js 20+, `npm install`, `npm start` (Java 21 requis sur le PC en développement).
- Installeur Windows : double-clic sur `build-windows.bat`, ou GitHub → Actions → « Build Windows ». Résultat dans `dist/` : installeur en un clic (sans droits administrateur) + exe portable. Java 21 est téléchargé par `scripts/fetch-jre.js` et embarqué.
- macOS / Linux : `npm run dist:mac` / `npm run dist:linux`, à lancer sur le système concerné.
- L’exe n’est pas signé : Windows affiche un avertissement tant qu’il n’y a pas de certificat.

## 2 bis. Java : comment il est choisi (v0.4)
Pour chaque lancement, `game.js` (`chooseJava`) décide dans cet ordre : **Java de l’instance** (page de l’instance › Paramètres) → **Java par défaut** (Paramètres › Java) → **automatique** : le Java demandé par Mojang pour cette version (champ `javaVersion.majorVersion` du manifeste, estimation par numéro si hors ligne), sinon le plus proche au-dessus, en 64 bits.
`platform.js` détecte les Java installés (Program Files, Java du launcher officiel, Prism, JAVA_HOME, PATH, Java embarqué) via `java -version`, et on peut en ajouter à la main (fichier java). Le journal de chaque lancement indique le Java utilisé, sa version, son éditeur, 32/64 bits et la version demandée.
Erreur « class file version N » : un fichier (jeu, loader ou mod) demande Java N-44 ; la notification de plantage le dit et propose de choisir ce Java. Rappel : version de classe 65 = Java 21, 69 = Java 25.
`scripts/fetch-jre.js` vérifie maintenant que le Java embarqué est bien en version 21 (sinon il échoue).

## 3. Architecture
```
src/main/        processus principal (Node) : toute la logique
  main.js        fenêtre sans cadre, canaux IPC, démarrage
  platform.js    TOUT ce qui dépend de l’OS (dossiers, Java, autres launchers)
  auth.js        Microsoft → Xbox → Minecraft (msmc), jetons chiffrés par le système
  game.js        versions Mojang, lancement, plantages expliqués, journal de jeu
  mods.js        loaders Fabric/Quilt, Modrinth, statuts, conflits, codes de partage
  servers.js     liste de serveurs + état en ligne (api.mcsrvstat.us)
  importer.js    import Prism / MultiMC / Minecraft officiel
  store.js       données locales (JSON, écriture atomique)
  log.js         journaux (voir 5)       notify.js   notifications système
  verified.json  liste des mods « Vérifiés » (viendra du serveur Hydarium)
src/preload.js   pont sécurisé : liste blanche des canaux IPC et des événements
src/renderer/    interface (HTML/CSS/JS), AUCUN accès direct à Node
  scene.js       décors pixel-art de la maquette (fonds d’écran, couvertures d’instances)
scripts/fetch-jre.js   télécharge Java 21 pour l’installeur
.github/workflows/build.yml   fabrication Windows dans le cloud
```
**Règle d’architecture** : l’interface ne fait que demander ; le processus principal décide et vérifie (noms, versions, identifiants de mods, adresses de serveurs sont revalidés côté main). Même principe que pour le futur serveur : le client n’envoie jamais de prix ni de solde.

**Ajouter un canal IPC** : (1) `on('mon:canal', fn)` dans `main.js`, (2) ajouter le nom à `CH` dans `preload.js`, (3) `call('mon:canal', …)` dans `app.js`. Un canal absent de `CH` est refusé.
**Ajouter une plateforme** : adapter uniquement `platform.js` (`roots`, `sub`, `otherLaunchers`), puis tester `npm run dist:<os>`.

## 3 bis. Interface (inspirée de la maquette)
Accueil (reprendre la dernière instance, récemment joué, serveurs, emplacements « bientôt » pour quêtes et amis), Vanilla, Moddé, Serveurs, Paramètres (Général, Apparence avec thème et 10 fonds d’écran dont « selon l’heure », Statistiques, Java, Aide et journaux), Profil (stats réelles, instances les plus jouées, compte), page d’instance (Mods, Mondes, Packs de ressources, Shaders, Captures, Paramètres : Java, mémoire, arguments JVM, stats).
Import manuel : bouton « Importer depuis un autre launcher… » (accueil, Vanilla, Moddé, Paramètres, assistant) : on choisit un dossier d’instances Prism/MultiMC, un dossier d’instance ou un dossier .minecraft (`importer.manual`).
Réglages : `store.settings` (`notif, minimize, autostart, wall, theme, mem, java, javas`), validés dans `set:set` (`main.js`).

## 4. Données (dossier utilisateur du système)
Windows : `%APPDATA%\hydarium-launcher\` · macOS : `~/Library/Application Support/hydarium-launcher/` · Linux : `~/.config/hydarium-launcher/`.
- `hydarium.json` : comptes (jetons chiffrés, jamais en clair), instances, serveurs, réglages, état de l’assistant.
- `shared/` : versions, bibliothèques et assets Minecraft partagés entre instances.
- `instances/<id>/` : dossier du jeu d’une instance (mods, mondes, options).
- `logs/` : journaux.
Une instance : `{ id, name, version, type, loader, mods[], mem, lastPlayed, playtime }`. Un mod : `{ pid, slug, title, file, incompat[], auto }`. Les mods importés ont un `pid` commençant par `imp` et sont « Non vérifiés ».

## 5. Journaux : quoi regarder en cas de problème
- `logs/launcher-AAAA-MM-JJ.log` : vie du launcher (démarrage, Java détecté, erreurs des canaux IPC, erreurs de l’interface). Conservés 14 jours.
- `logs/game-<instance>-<date>.log` : un fichier par lancement. Première ligne = contexte (version, loader, Java, mémoire), puis arguments de lancement et toute la sortie du jeu, puis le code de fermeture.
- Les jetons de connexion sont masqués automatiquement.
- Plantage : notification « Plantage : <instance> » avec la cause en français (Java incompatible, mémoire, mod incompatible, etc., liste `KNOWN` dans `game.js`) ; cliquer ouvre le journal. Si la cause est inconnue, lire la fin du journal de jeu et le rapport de plantage du dossier `crash-reports` de l’instance.
- Paramètres → « Copier le rapport » : met dans le presse-papiers un rapport complet à coller dans une demande d’aide.
- **Pistes pour « le jeu s’est fermé de façon inattendue »** : Java trop ancien ou trop récent pour la version de Minecraft ; mémoire trop haute pour le PC (baisser dans la page de l’instance) ; mod incompatible ; profil Fabric non reconnu ; session Microsoft expirée.

## 6. Notifications
Toujours de vraies notifications système (`notify.js`, API Notification d’Électron), jamais de bulle dans la fenêtre. Windows exige l’identifiant d’application `fr.hydarium.launcher` (déjà défini dans `main.js` et `package.json`) ; en développement (`npm start`) elles peuvent ne pas apparaître avant d’avoir installé l’exe. Activables / désactivables dans Paramètres. Dans l’interface, utiliser `note(message, titre)`.

## 7. Assistant de bienvenue (inspiré de la maquette)
Bienvenue → connexion Microsoft → import depuis un autre launcher → terminé. Se relance depuis Paramètres. L’import copie mods, mondes, packs de ressources, shaders, captures, configuration et options ; Forge n’est pas géré (instance ignorée avec message). MultiMC portable (dossier libre) n’est pas détecté automatiquement.

## 8. Pièges connus
- Fabric/Quilt : le profil est téléchargé dans `shared/versions/` puis passé à `minecraft-launcher-core` via `version.custom`. **Non testé** ; premier endroit à vérifier si un lancement moddé échoue.
- Rejoindre un serveur : `--quickPlayMultiplayer` (1.20+) ou `--server/--port` (avant). Une option refusée plante le jeu (cause « Option non reconnue »).
- Java embarqué = 21 : suffisant pour les versions récentes, pas pour les très anciennes (1.16 et avant).
- `msmc` / `minecraft-launcher-core` : versions à épingler et à tester au premier `npm install` (les noms de méthodes ont pu changer).
- L’état « en ligne » des serveurs dépend d’un service public gratuit.

## 9. Prochaines étapes conseillées
1. Premier test réel sur Windows, corriger ce que les journaux montrent.
2. Icône `.ico`, signature de l’exe, mise à jour automatique.
3. Captures d’écran, puis amis (nécessite le serveur Hydarium).
4. Serveur Hydarium : comptes, liste des mods vérifiés, codes courts, puis quêtes / cosmétiques / points (voir le cahier des charges v1.9 et `hydarium-site.html`).
5. Forge / NeoForge, import CurseForge / Modrinth App, langues.

## 10. Version 0.9.0 : ce qui a changé
- **Bug de saisie / listes qui se referment** : l’interface se redessinait pendant la saisie (rendus asynchrones concurrents, `confirm()` natif qui bloque le focus dans Électron). - **Page d’instance** : mods (activer / désactiver, importer un .jar, icônes), mondes (icône, jouer directement dans un monde 1.20+, sauvegarde, copie, suppression, import dossier/zip), packs de ressources et shaders (téléchargement Modrinth, activation via `options.txt` / `iris.properties`), captures, paramètres (nom, catégorie, notes, couverture, Java, mémoire min/max, préréglage JVM, résolution, options du jeu, serveur automatique, arguments, dossiers).
- **Navigateur Modrinth** (`content.js`) : populaires par défaut, recherche, icônes ; utilisé pour mods, packs, shaders et pour la création d’instance.
- **Nouvelle instance** façon maquette (version, loader, optimisation, puces de mods, couverture) avec progression.
- **Captures** : nouvelle page qui regroupe celles de toutes les instances (`shots.js`).
- **Profil** : skin 2D face/dos (canvas), bibliothèque de skins (import PNG, skin d’un joueur, export), capes (`skins.js`, API Mojang). Nouvelle dépendance : `adm-zip` (import de mondes .zip) → `npm install`.
- **Pas fait** : mondes partagés entre instances Vanilla (risque de perte de données avec les liens symboliques), Bedrock/Legends/Dungeons, quêtes/cosmétiques/amis/chat. Tout est **testé en simulation (jsdom, tests unitaires)** mais pas encore dans Électron réel.

### Idée pour `nom.hydarium.…`
DNS joker `*.hydarium.xx` vers un proxy Minecraft qui lit l’adresse demandée dans la poignée de main (type Velocity / mc-router) et relaie vers la machine du joueur par un tunnel sortant (ainsi pas de redirection de port chez lui). Les comptes et noms viendront du serveur Hydarium.

## 0.10.50 — fin de l'ouverture de ports, invitations privées P2P, onglet Crédits
Décisions de Gazein : **Hydarium n'ouvre plus aucun port sur la box** (jugé dangereux) ; playit.gg reste ; à côté, un mode **P2P sans relais** pour jouer entre utilisateurs d'Hydarium ; un onglet **Crédits**.

Tunnel fermé après 15 min sans connexion, à la suppression de l'entrée, ou en quittant.
- **Sécurité** : la clé de l'hôte se dérive du code, MAIS entrer exige une preuve HMAC (défi aléatoire + les deux clés de la connexion) : un intrus qui connaît la clé publique est coupé et **le serveur Minecraft ne reçoit rien** (testé). ## 0.10.51 — playit.gg refait : adresse détectée, un tunnel par serveur, bons liens
Symptômes de Gazein : l'agent s'active mais **aucune adresse** ne s'affiche ; impossible de **changer l'adresse du tunnel** ; impossible d'avoir **un tunnel par serveur** ; les liens **n'envoient pas au bon endroit**.
- **Cause racine (vérifiée dans le code source officiel `playit-cloud/playit-agent`, branche master, et les fichiers de la v1.2.0)** : depuis la série 1.x l'agent est un **démon** (`playitd`) piloté par un client ; il n'écrit plus rien d'exploitable sur sa sortie. L'ancien `playit.js` lisait un texte (`xxx.ply.gg:123 => 127.0.0.1:25565`) qui n'arrive jamais, **et** téléchargeait le mauvais fichier (`playit-windows-…exe` = client interactif, avec une exclusion explicite de `playitd`). Aucune adresse ne pouvait donc être détectée. Un projet tiers (RealmSwap, PR 125) a fait le même constat.
- **Nouveau `playit.js`** : on parle à l'API (`https://api.playit.gg`, enveloppe `{status: success|fail|error, data}`) comme les clients officiels. (1) **Liaison** : code de 10 hexadécimaux → lien `https://playit.gg/claim/<code>` → `POST /claim/setup` (sans auth, `agent_type: "assignable"` comme la CLI officielle, `version: "playit <version du démon>"`) jusqu'à `UserAccepted` → `POST /claim/exchange` → `secret_key`, rangée dans `<données>/playit/playit.toml` (`secret_key = "…"`, accepté tel quel par le démon). (2) **Démon** : `playitd --secret-path <fichier> --socket-path <tube> --log-path <journal>` (la clé passe par fichier, jamais en clair dans la ligne de commande ; aucun service Windows installé). (3) **Adresse** : `POST /v1/agents/rundata` (en-tête `Authorization: Agent-Key <clé>`) toutes les 4 s ; chaque tunnel donne `display_address` et `agent_config.fields` (`local_ip`, `local_port`). (4) **Un tunnel par serveur** : `POST /v1/tunnels/create` (Minecraft Java → `127.0.0.1:<port du serveur>`) ; **changer d'adresse** = repointer un tunnel existant avec `POST /v1/tunnels/config`.
- **Installation** : `assetFor` choisit maintenant `playitd-windows-<arch>[-signed].exe` (jamais le client, ni le tray, ni les .msi). **Linux/macOS : aucun `playitd` autonome n'est publié** dans la v1.2.0 → message clair (installer playit depuis playit.gg ; un `playitd` dans le PATH est utilisé). L'ancien client téléchargé par 0.10.49/0.10.50 est supprimé. Empreinte SHA-256 toujours obligatoire (présente sur tous les fichiers de la v1.2.0). La version du démon est mémorisée (`version.txt`) pour l'annoncer comme le fait l'agent officiel (le serveur de playit tient compte de la version : `AgentVersionTooOld/Unknown`).
- **Interface** : le champ « adresse du tunnel » est **toujours** là (avant, il n'existait que « en marche » : impossible de changer l'adresse dans les autres états) ; bouton **Créer un tunnel pour ce serveur** (port + nom) ; **liste des tunnels du compte** pour en reprendre un (« Utiliser ce tunnel pour ce serveur » ; prévient que l'ancien serveur le perd) ; « Relier un autre compte » ; messages d'erreur de playit traduits (compte à vérifier par e-mail, Premium, agent non lié…). « Gérer mes tunnels » ouvre **`https://playit.gg/account/tunnels`** (plus l'accueil du site) ; « Page de téléchargement » ouvre `playit.gg/download` ; le lien de liaison n'est ouvert que s'il correspond au format `https://playit.gg/claim/…`.
- **Adresse enregistrée toute seule** (`host.syncPlayit`, appelé à chaque évènement `playit:state`) pour le serveur dont le port a un tunnel, **sans jamais écraser** une adresse saisie à la main (on ne remplace que ce qu'on avait écrit : `h.playitAuto`). La carte « Adresses » affiche l'adresse détectée.
- **Sécurité / confidentialité** : Hydarium détient maintenant la **clé de l'agent** (fichier local, droits 0600) : elle permet de créer des tunnels sur le compte playit de la personne. Elle ne va qu'à api.playit.gg. « Relier un autre compte » l'efface.
- **Tests** : `playit.test.js` réécrit (221 contrôles) avec une **fausse API** et un **faux démon** : liaison, clé rangée, arguments du démon, adresse détectée, deux serveurs/deux tunnels, création/doublon/erreurs, repointage, coupure réseau, clé refusée, refus/expiration de la liaison, plantages du démon, installation avec empreinte, carte de l'interface. `legacyports.test.js` : 70 contrôles.
- **NON essayé en vrai** : l'échange avec `api.playit.gg` (pas de compte, pas d'accès). Les formats viennent du code source officiel ; `/claim/setup` et `/claim/exchange` sont ceux de la CLI officielle (`agent_type: assignable`), mais **`/v1/tunnels/create` et `/v1/tunnels/config` appelés avec une clé d'agent « assignable »** n'ont jamais été vus fonctionner en vrai (RealmSwap, qui les utilise, le dit aussi) : à tester sur un vrai Windows. Si playit refuse la création (ex. `RequiresVerifiedAccount`), le message s'affiche ; le repli est de créer le tunnel sur playit.gg (« Gérer mes tunnels », type Minecraft Java, port du serveur) : l'adresse est alors détectée toute seule. Si l'agent « assignable » ne convenait pas, essayer `agent_type: "self-managed"` (ligne `claimFlow`).
